## 一、为什么先做 Capability 而不是 P2-B

上一轮查 6 个网络消息的依赖时发现：**它们全部依赖 Capability / Action 类**。而这次把依赖链完整挖开后，结论更明确：

```
SyncStaminaMessage / SyncStaminaToClientMessage
        └─> IStamina ──> ParCoolStamina ──> Parkourability.getActionInfo()
SyncClientInformationMessage / SyncServerInfoMessage
        └─> ClientSetting / ServerLimitation ──> ActionList + Action
SyncActionStateMessage / StartBreakfallMessage
        └─> Parkourability ──> ActionList + Action
                                    └─> 26 个 Action 实现类  ← ★ 全链路的瓶颈
```

**`ActionList`（及其 26 个 Action 实现）是唯一的总瓶颈。** 它属于 P4。
所以 P3-A 的策略是：**把不依赖 `ActionList` 的部分先做完**，让 Capability 链路通、可挂载、可读取。

### 怎么区分「本地玩家」—— 用 `@SidedProxy` 而不是 `instanceof EntityPlayerSP`

上游用 `player.isLocalPlayer()`（1.16 的 `PlayerEntity` 有这个方法）。**1.12.2 没有。**

而 1.12.2 惯用的替代 `player instanceof EntityPlayerSP` 有个陷阱：`StaminaProvider` 是**双端加载**的类，`instanceof` 会让专用服务端去解析客户端类，有 `NoClassDefFoundError` 风险。

**做法**：新增 `CommonProxy.isLocalPlayer(EntityPlayer)`（恒返回 false），
由 `@SideOnly(Side.CLIENT)` 的 `ClientProxy` 覆写为 `player == Minecraft.getMinecraft().player`。
`@SidedProxy` 保证服务端不会加载客户端代理 —— 这是**硬保证**，不依赖 FML 运行期剥离。

## 三、⚠️ 两条被修正的 API 记录（此前我记错了）

### 1. `CapabilityManager.register` 在 1.12.2 **有工厂重载**

我之前写「1.12.2 只有两参数重载，工厂要挪进 Provider」——**错的**。反编译源码有两个三参重载：

```java
// net/minecraftforge/common/capabilities/CapabilityManager.java
:57  public <T> void register(Class<T> type, Capability.IStorage<T> storage, final Class<? extends T> implementation)
:79  public <T> void register(Class<T> type, Capability.IStorage<T> storage, Callable<? extends T> factory)
```

所以上游那句
```java
manager.register(IStamina.class, new StaminaStorage(), ParCoolStamina::new);
```
**在 1.12.2 可以直接照搬**（`ParCoolStamina::new` 匹配无参构造 → `Callable<? extends IStamina>`）。

### 2. `ICapabilityProvider` 在 1.12.2 **还要求 `hasCapability`**

```java
// net/minecraftforge/common/capabilities/ICapabilityProvider（1.12.2）
<T> T getCapability(Capability<T> capability, EnumFacing facing);
boolean hasCapability(Capability<?> capability, EnumFacing facing);   // ← 1.13+ 删掉了
```

照抄上游 Provider 会报「未覆盖抽象方法 `hasCapability(Capability<?>, EnumFacing)`」。
**已加入 P1-B/P3 的核对清单**：凡是从 1.13+ 版本抄 Provider，都要补这个方法。

### 3. 其余差异（本轮实际遇到的）

| 项 | 1.16.5 | 1.12.2 |
|---|---|---|
| `LazyOptional` | 有 | **无** → 直接返回实例或 `null` |
| `getCapability` | 单参数 | `getCapability(Capability<T>, EnumFacing)` |
| `ICapabilitySerializable<T>` | `T extends INBT` | `T extends NBTBase` |
| `IStorage.writeNBT` 返回 | `INBT` | `NBTBase` |
| `Direction` | — | `EnumFacing` |
| `AttributeModifier(uuid,name,amount,Operation)` | 枚举 | **`int`**（0=ADDITION），且 `addTransientModifier` → `applyModifier` |
| `Attributes.MOVEMENT_SPEED` | Forge 的 | `SharedMonsterAttributes.MOVEMENT_SPEED` |
| `ModifiableAttributeInstance` | — | `IAttributeInstance` |
| `getFoodData().getFoodLevel()` | — | `getFoodStats().getFoodLevel()` |
| `causeFoodExhaustion` | — | **`addExhaustion`** |
| `hasEffect` | — | `isPotionActive` |

## 四、明确标注的 TODO（4 处，全部指向 P4）

| 位置 | 上游原逻辑 | 过渡期现状 |
|---|---|---|
| `ParCoolStamina.getActualMaxStamina()` | 属性值与 `ActionInfo.getMaxStaminaLimit()` 取较小 | 只用属性值 |
| `ParCoolStamina.tick()` | 恢复量受 `getStaminaRecoveryLimit()` 限制 | 只用属性值 |
| `ParCoolStamina.consume()` | 查 `ActionInfo.isStaminaInfinite(...)` | 只判创意/旁观/效果 |
| `OtherStamina.tick()` | 还查 `ClientInfo.get(EnableStaminaExhaustionPenalty)` | 直接应用惩罚（等价开关为 true） |
| `HungerStamina.consume()` | 同上 isStaminaInfinite | 只判创意/旁观 |
| `StaminaProvider` | 按 `ParCoolConfig.Client.StaminaType` 选实现 | 固定 `Type.Default` |

**为什么过渡期不会产生错误行为**：缺的全是「服务端把上限压下来」和「按客户端设置决定是否惩罚」。
本地客户端在正常场景下打不到上限，所以游戏行为正确，**只是缺少服务端限制能力**。
接回时只改这 6 处，其余逻辑不动。

## 五、实机验证

装上 jar 后，启动日志自检应多出第 14 项：

```
14. Stamina capability    : OK (injected, location=parcool:capability.stamina)
```

判读：

| 现象 | 结论 |
|---|---|
| `OK (injected, ...)` | ✅ `@CapabilityInject` 注入成功、`Capabilities.register()` 时机正确 |
| `FAILED  <<< Capabilities.register() 未调用或时机过晚` | `ParCool.preInit` 里的 `Capabilities.register()` 没跑到 |
| 启动即崩且提到 `hasCapability` | 版本不对（说明拿 1.13+ 的 Provider 改了它） |

**进世界后可以顺手确认实例真的挂上了**（`ClientInGameCheck` 里加一行即可）：
```java
LOGGER.info("stamina = {}", IStamina.get(mc.player));   // 期望不是 null
```
我**没有**把这行加进去 —— 因为 `IStamina.get` 返回 null 时 logger 打印 `null`，
而真正要看的是「是否非 null」。若你要验，加这行即可；不加也不影响（第 14 项已经证明注册成功）。
